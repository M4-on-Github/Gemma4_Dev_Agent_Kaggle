lucky draw.

## Why

- **A task that finishes on its own resolves far more often than one that is cut.** R-037 kfctl ×8, per draw of 79:
  46.5 tasks end by submitting with a patch and 26.25 of them resolve (0.56); 32.1 are cut by a cap and 4.12 resolve.
- **The Kaggle run serves one model stream at a time**, so GPU batch capacity is idle. Several attempts on one task
  overlap their model calls. `submit_patch` ends the task, so the task ends at the fastest finisher.
- **Desk simulation on the 8 kfctl draws** (`$CLAUDE_JOB_DIR/tmp/race.py`; every attempt taken from a different draw,
  first non-empty finisher wins, else the first attempt's tree as left):

  | Attempts | Per-stream slowdown | Solves per 79 | SD over draws | Wall ratio |
  |---|---|---|---|---|
  | 1 (kfctl) | - | 30.38 | 2.64 | 1.000 |
  | 3 | 1.00 | 32.47 | 1.58 | 0.848 |
  | 3 | 1.15 | 31.74 | 1.46 | 0.944 |
  | 3 | 1.30 | 30.51 | 1.54 | 1.029 |

  The gain depends on the slowdown from sharing the GPU, which is not known for Kaggle. The spread between draws
  falls in every row.

## Smoke 1 (job 67964, 2026-11-26): FAIL, fixed once

- 2 tasks, both served; three branches made tool calls in both; b and c made their worktrees in both.
- Task 1: branch b applied its diff and submitted; resolved. Branch c made 1 edit outside its worktree.
- Task 2: the run crashed at 212 s with an ADK `ValueError` (a function response with no matching call in the
  branch's history), raised from the history assembly under `ParallelAgent`. Empty patch.
- **Cause (source read):** the scorer's history compaction works on the whole session, so with three branches in one
  session it cuts across them. R-016 showed an `agent_tool` runs in its own session without compaction.
- **Fix 1 (before smoke 2):** each branch is now a small runner (`runner_a..c`, thinking 256, R-016's root sampling)
  whose only tool is its solver as an `agent_tool` (`solve_a..c`, the R-016 solver prompt form with the issue in the
  instructions). Solver prompts and tools are otherwise unchanged from smoke 1.

## Smoke 2 (job 67965, 2026-11-26): FAIL on design, fixed a second and last time

- No crash: fix 1 holds. Both tasks served, three solvers active, both worktrees made in both tasks.
- Task 1: resolved. All three solvers submitted (at 330 s, 354 s, 397 s) and the task ended at 420 s.
- Task 2: time cap, empty patch. One side solver called `submit_patch` without running its copy command (0 files).
- **Flaw 1: a `submit_patch` inside an agent_tool does not end the task** (source read: the run ends on a text reply
  in the root stream after a submit, and `skip_summarization` suppresses that reply). The task ran to its slowest
  branch and the last copy command won, not the first.
- **Flaw 2: the copy-then-submit step was left to the solver, which skipped it once in four side runs.**
- **Flaw 3: side solvers edited a file under `/workspace` in 2 of 2 tasks**, where branch a works.
- **Fix 2 (before smoke 3):**
  - all three solvers work in worktrees; none holds `submit_patch`; each ends by replying DONE;
  - each runner (no `skip_summarization`) then runs one fixed command that takes a lock (`mkdir`), resets
    `/workspace` and applies its solver's diff, and prints APPLIED, EMPTY or TAKEN; on APPLIED it calls
    `submit_patch`; it then replies, which ends the task;
  - cost, stated: with no branch in `/workspace`, a task where no solver finishes is graded empty.
- **Deviation (logged before smoke 3 and before any draw):** smoke 3 and the draws run at `--concurrency 1`
  (3 model streams per GPU), not 2. At 6 streams smoke 2 showed single model turns of 140-200 s. With 3 streams
  against the control's 4, the screen is, if anything, faster per stream than the control; the wall reading is
  reported with that caveat and the Kaggle timing run stays the deciding measurement. A draw takes about 8 h.
