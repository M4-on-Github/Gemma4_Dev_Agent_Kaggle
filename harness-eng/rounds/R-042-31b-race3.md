## Why

- **A task that finishes on its own resolves far more often than one that is cut.** R-037 kfctl ×8, per draw of 79:
  46.5 tasks end by submitting with a patch and 26.25 of them resolve (0.56); 32.1 are cut by a cap and 4.12 resolve.
- **The Kaggle run serves one model stream at a time**, so GPU batch capacity is idle. Several attempts on one task
  overlap their model calls. `submit_patch` ends the task, so the task ends at the fastest finisher.
- **Desk simulation on the 8 kfctl draws** (`$CLAUDE_JOB_DIR/tmp/race.py`; every attempt taken from a different draw,
  first non-empty finisher wins, else the first attempt's tree as left):

  | Attempts | Per-stream slowdown | Solves per 79 | SD over draws | Wall ratio |
  |---|---|---|---|---|
  | 1 (kfctl) | - | 30.38 | 2.64 | 1.000 |
  | 3 | 1.00 | 32.47 | 1.58 | 0.848 |
  | 3 | 1.15 | 31.74 | 1.46 | 0.944 |
  | 3 | 1.30 | 30.51 | 1.54 | 1.029 |

  The gain depends on the slowdown from sharing the GPU, which is not known for Kaggle. The spread between draws
  falls in every row.

- **Tree.** Root `ParallelAgent` with three copies of the `31b-base` agent, all six tools each.
  - Branch a: the base prompt, unchanged, in `/workspace`.
  - Branches b and c: the base prompt plus two sections. Each makes a git worktree under `/workspace/.git`, works
    there, and before `submit_patch` runs one fixed command that resets `/workspace` and applies its diff.
  - `max_tool_calls` 90 and `max_turns` 240 (one budget for the task); `max_time_minutes` 9.9 as kfctl.
- **Limits of the screen, stated before it runs.**
  - The control is not concurrent with the arm.
  - The arm runs 6 streams per GPU against the control's 4. This stands in for Kaggle's slowdown at 3 streams, which
    is unmeasured. A promote here is "worth a Kaggle notebook timing run", not "ship".
- Cohort `cohorts/cdev2-79.txt`; flags as R-037 except `--concurrency 2`. About 8 × 4 h on 1 Ada GPU each.
