Read through the fetch tool on 2026-11-05 (HTML v1, queried for §2.2, §2.3, Table 1, Fig. 5/6 captions, Appendix A). Per-method numbers for majority voting and model-only selection appear only in Figure 6 and were not available as text.

## Takeaway
Best published decomposition of generate-many then select on SWE-bench Verified: random pick 45.8%, final selected 57.4%, oracle (coverage) 69.8%. The selector is test-first, and a model-only selector is worse than test voting unless it runs after test filtering. Base model is Claude 3.5 Sonnet, so this is the ceiling of the family with a strong model, not our case.

## Method
- 10 (testing, editing) state-machine pairs per issue; each editing machine iterates up to 8 serial iterations (§2.2, Fig. 5). Candidates differ by sampling; the model writes a reproduction script per pair (§2.2).
- Selection (§2.3): run each of the 10 generated tests on each of the 10 edits (100 test runs per problem), keep the top 3 edits by tests passed, then a selection state machine in which the model reads the candidates and runs further model-written tests that discriminate between them; each new test is run on every remaining candidate plus the unedited code.
- Relevance scan with Qwen2.5-Coder-32B-Instruct run locally (§2.1, Appendix C).

## Relevance
Answers part A on same-model judging: an LLM reading candidate diffs, without execution evidence, was worse than counting how many model-written tests each passes, and better only on top of that filter. Selection is 6.7% of cost; the testing that feeds it is about 19% plus the 100 executions, which for us is wall-clock we do not have.

Transfers to our constraints: partly. Frontier model, thousands of dollars, 100 test executions per issue. The ordering result (tests first, judge second) is the transferable part.

## Ideas to test
- (mine) If a judge is used, give it the test outcomes: a same-model chooser prompt shown the exit codes of the repo tests and one reproduction script per candidate picks the resolving candidate more often than the same prompt shown diffs only. Falsifiable on any set of 2 to 3 candidate pairs with known outcomes (EXP-034).

## Caveats
Single base model for everything except the scan; no wall-clock; majority voting and model-only numbers unread.
