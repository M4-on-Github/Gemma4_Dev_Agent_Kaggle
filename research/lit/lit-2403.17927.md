## Takeaway
A four-role pipeline (Manager, Repository Custodian, Developer, QA Engineer) on GPT-4. The QA-engineer ablation is a same-model reviewer ablation on SWE-bench: removing it costs 3.3 points on the full set and 2.0 on Lite.

## Method
- Base model GPT-4 for all roles (§4.1). QA Engineer reviews the Developer's code change; ablation "bypassing the QA process" (§4.2). "Hints" are PR comments (§4.2).

## Relevance
Part C: a same-model QA reviewer contributes +2 to +3 points, smaller than the hints (+5 on full, +8.7 on Lite); the "hints" are PR comments, which a deployed agent does not have. Gains are measured against the 2024 GPT-4 direct baseline at 1.74%, so the pipeline-versus-loop comparison is not made.

Transfers to our constraints: partly. GPT-4, 2024 baselines, the QA stage re-runs through the Developer.

## Ideas to test
- (mine) Claim: a QA-style review stage after the edit changes the final diff in under 15% of tasks; whatever it adds is capped by that rate, so with a base resolve rate near 0.2 it can add at most about 3 points.

## Caveats
No loop baseline; hints leak information.
