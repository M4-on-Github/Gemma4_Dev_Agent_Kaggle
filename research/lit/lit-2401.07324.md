Read through the fetch tool on 2026-11-05 (Table 1, §3.4, §4.3, §5.1). Title is from memory of the arXiv listing, unverified. Trained and not about code repair; kept as the only small-model split-roles datum found.

## Takeaway
Splitting one 7B model into a planner, a caller and a summarizer (three fine-tuned models) beats one fine-tuned 7B on tool-use benchmarks, because "limited model capacity hinders the agent from effectively fulfilling the roles of planner, caller, and summarizer simultaneously" (§5.1).

## Reported results
| Quantity | Value | Where |
|---|---|---|
| 7B single-LLM vs alpha-UMi (w/ reuse), in-domain plan accuracy / action EM | 81.92 / 53.26 vs 88.92 / 58.94 | Table 1 |
| 13B single-LLM vs alpha-UMi | 81.01 / 59.67 vs 87.87 / 63.03 | Table 1 |
| Size effect | 7B alpha-UMi "even outperforms the Single-LLM baseline with a 13B LLM" | §5.1 |

## Relevance
Part E, weak. Narrow roles help a small model only when each role is trained on its role; we cannot train, and our roles would be prompts over one untrained model (see lit-2601.12307 for the no-gain case with a single prompted model).

Transfers to our constraints: no (fine-tuning of three models, tool benchmarks).
